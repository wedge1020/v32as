# v32as — Vircon32 assembler and linker

`v32as` assembles Vircon32 assembly language into a VBIN file, the format of a cartridge program. Given the same
source it writes the same bytes as the official `assemble` tool, and it adds a preprocessor with macros, a few
extra number forms, relocatable objects with a linker (`v32asld`), a listing/verbose/step mode, an interactive
mode, and several debug outputs. `--standard` turns every extension off.

It is written in C: the lexer is generated by flex, the parser by bison, and symbols and fixups live in hash
tables. The tools are `bin/v32as` (the assembler) and `bin/v32asld` (the linker and archiver).

## Build, install, and test

```
    make            # builds bin/v32as and bin/v32asld  (needs flex, bison, cc; readline optional)
    make test       # differential/golden tests (including .debug files) (sh + od + cmp + grep only)
    make install    # v32as, v32asld, lib/*.inc and the man pages into ~/bin, ~/share/v32as/lib and ~/man
    make install PREFIX=/usr/local     # or any other PREFIX: PREFIX/bin, PREFIX/share/man, PREFIX/share/v32as/lib
    make sysinstall # make install PREFIX=/usr/local
    make uninstall  # removes what install put there (same PREFIX/DESTDIR/BINDIR/MANDIR/LIBDIR)
    make mancheck   # lints the man pages (plain sh and awk, no groff needed)
    make archive    # ../v32as-project.zip, without build products
```

`install` honours `DESTDIR` (for packaging) and the directories can be set one by one: `BINDIR`, `MANDIR`,
`LIBDIR`. `make debug` builds with `-g -O0`. GNU readline is used for the interactive mode when its development
files are found (`make READLINE=0` to opt out). `make clean` removes the build products.

Layout: `src/` sources (flex, bison, C), `inc/` headers, `lib/` macro libraries for `%include`, `man/` manual
pages, `docs/` design notes, `tests/`, `experiments/`; `make` puts generated files in `build/` and the tools in
`bin/`.

## Usage

```
    v32as [-b|-c|-O ADDR] [-o FILE] [-g[MODE]] [--map FILE] [-r FILE] [-w] [-D NAME[=VAL]] [-U NAME] [-I DIR]
          [--rom-xml FILE] [--build-scripts[=sh,bat]] [--standard] [-T|-n] [-E [-P]] [-s] [-v] [FILE...|-]
```

By default `v32as FILE.asm` does what the official `assemble FILE.asm` does: it writes `FILE.vbin`,
a VBIN for a cartridge. (Reading STDIN, the output goes to STDOUT.)

- No files and a terminal on stdin starts the interactive mode (REPL): each line is assembled as soon as it is
  entered; the commands are `.help .labels .dump .reset .quit`.
- `-` reads stdin; the legacy bare words (`bios`, `cart`, ...) still work.
- Multiple input files share one preprocessor state (macros, defines, contexts).
- Errors and the `-g` file point at the file and line you wrote, also through `%include` and macros (on a
  line where a macro expanded, the column is left out).
- Memory (2026-10-27, so that v32as runs on v32nix): a named file goes through the preprocessor a line at a time, the
  preprocessor's output is scanned in place, each file-local label is remembered once, and the debug records and the
  address list are kept only for `-g`, `-r`, `-C` and `--symbols-all`. The output is the same.

Exit status: 0 on success (warnings do not change it), 1 for an assembly or preprocessor error or an unreadable input
file, 2 for a usage error (bad or conflicting options) or an output file that cannot be written. `v32asld` uses the
same: 1 for a link error, 2 for a usage error or a bad object.

## Option reference

This is the single list of options of `v32as`. `v32as --help` prints the same list in short form; the manual page
`v32as(1)` has the full text.

### Output and target

- `-o, --output=FILE` names the output. The default is the input file with its extension replaced by `.vbin`
  (`.v32ob` with `-C`), or STDOUT when reading STDIN.
- `-b, --bios` assembles for the BIOS (0x10000000); `-c, --cart` for a cartridge (0x20000000, the default);
  `-O, --origin ADDR` for any base address.
- `--v32x` (with `--origin`) writes a v32nix executable instead of a VBIN: an 8-word header (`V32X`, version 1, header words, program
  words, data words, entry 0, origin, flags 0), then the program. The data words (zeroed by v32nix's `exec` after the program) come from
  `--v32x-data N`, or from the source's `%define __V32X_DATAWORDS N` (what `v32cc --data-after-text` writes). On the console a file
  word is a machine word, as v32nix's `exec` reads it.
- `-T, --text` prints a human-readable listing (the instruction encodings) instead of writing a VBIN.
  Its addresses start at 0 unless `-b/-c/-O` is given. `-n, --none` is `-T` with no base address.
  (`-B, --binary` still exists, and only says what is already the default.)
- `-C, --object` writes a relocatable object `FILE.v32ob` for the linker; see [Objects and the linker](#objects-and-the-linker).
  It cannot be combined with `-b -c -O -g -r -T -n -E -B` or `--standard`; `--map` is allowed.

### Debug and symbol outputs

- `-g, --debug[=MODE]` also writes `OUTPUT.debug` (CSV `address,file,line[,label]`, one line per instruction; with `;@src` markers in the
  source, one per marker) next to the output file. Plain `-g` is byte-identical to the official assembler's `-g program` (absolute word addresses,
  e.g. `0x20000000`). `-g vbin` / `-g v32` give real byte offsets in the .vbin (0x0C header) or .v32 (0x8C header) file; the official tool's
  versions of those two print wrapped-around values. A source file literally named `program`, `vbin` or `v32` must be written `./program`.
  Format: [The .debug file](#the-debug-file). With `;@var` lines in the source, `OUTPUT.vars` is written as well, and `OUTPUT.sym`
  always (not with `--standard`): [The .sym file](#the-sym-file).
- `--map FILE`: FILE is the compiler's debug file (`asmfile,asmline,cfile,cline[,function]`, as `v32cc -g` writes it). The `.debug` file then has
  the same layout, but each instruction names the C file and line (and the function as the label column), which is what v32sim's C overlay reads.
  Instructions whose assembly line is not in FILE are left out. `--map` also works with `-C` and for diagnostics:
  - File names are compared exactly first, then by base name (the longest shared directory tail wins), so `main.asm` in the map matches
    `out/kernel/main.asm`. If no instruction matches at all, a warning names the names found in the map.
  - With `--map FILE` (no `-g` needed) every error and warning of the assembler or the preprocessor is followed by
    `a.c:123: note: the assembly line above was generated from here` (the function is named when the map has it), or, for a line with no
    entry of its own, by `... it follows the code generated from here` naming the nearest earlier mapped line.
  - With `-C` the object stores the C file and line (and the function) of each instruction in place of the assembly ones; instructions the map
    does not know are left out, as in `-g --map`. `v32asld -g` then writes the C-level `.debug` file, the same as `v32as -g --map` would on the
    joined source.
- `-r, --relocs FILE` writes `index,0xVALUE` for every word that holds an address resolved from a label (code or data, `label+N` included) or
  computed from the instruction's own address (`MOV Rn, IP`, the `IR`/`IV` patch addresses). Plain numbers that happen to look like addresses
  are never listed, so a loader can relocate a module by adding the base difference to those words. Format: [The -r file](#the-r-relocation-file).
- `--symbols FILE` writes `address,name,kind` per label, sorted by address; kind `F` (code follows), `D` (data follows, or nothing).
  `--symbols-all` adds file-local labels as `function.local` and every `%define global_NAME number` as kind `V`, and every `DATASYM+N` the
  program refers to (see `datasym`) as `N,DATASYM+N,V`: the offset in the address column. Not available with `-C` (use `v32asld --symbols`).
- `-MD`, `-MMD`, `-MP`, `-MF FILE`, `-MT TARGET` write the sources, `%include` files and `datafile` files read, as a Makefile rule (default
  file: the output name with `.d`). `-MF` and `-MT` imply `-MD`; `-MP` adds an empty rule for each dependency that is not a named source.

### Preprocessor

- `-D, --define NAME[=VALUE]` (the value defaults to 1), `-U, --undef NAME`, processed in command line order.
  A `%define` of a `-D` name warns (the file still wins); `-D!NAME=VALUE` or `--force-define NAME=VALUE` makes the command line win.
  A `%define` that changes a macro's value warns too (`-Wredefine`, on by default; `-Wno-redefine`, `-w` and `--standard` silence it). `-Wno-redefine` does
  not silence the warning about a `-D` name; `-w` does.
- `-I, --include DIR` adds DIR to the search path of `%include` and `datafile` (may be repeated).
- `-E, --preprocess` prints the preprocessed source with `# LINE "FILE"` markers; `-P` (with `-E`) leaves the markers out.
- `-Wmarkers` (off by default; `-Wno-markers`) warns about a `;@src` whose `FILE:LINE` is malformed (no `:`, a line that is not a number >= 1,
  nothing after `;@src`), a `;@var` (no NAME or no `loc=`), a `;@scope` (not `{` or `}`), an unbalanced `;@scope }` and a block left open.
  Such a `;@src` is treated as `;@src -` (entry `-,0`): no source is better than a wrong line. `-w` silences it.

### ROM definition and build scripts

All of these are extensions (an error under `--standard`) and need a BIOS or cartridge VBIN written to a file (not `-C`, `-T`, `-n`, `-E`,
`-O`, `--v32x` or STDIN). Nothing is written unless one of them is given: a plain `v32as FILE.asm` still writes only `FILE.vbin`.
The whole feature is described in [Cartridge definition and build scripts](#cartridge-definition-and-build-scripts).

- `--rom-xml FILE` also writes the ROM definition `packrom` reads, from the source's `%title`, `%version`, `%texture` and `%sound`.
- `--rom-xml-opt FILE` writes the same for the build made from `v32opt`'s output (binary `NAMEOpt.vbin`, title `<title> [optimized]`).
- `--build-scripts[=FORMATS]` writes `Make.sh` and `Make.bat` (FORMATS: `sh`, `bat` or `sh,bat`, the default) next to the first source (in its parent
  for a `src/` + `obj/` layout), and the definitions they use (`NAME.xml`, `NAMEOpt.xml`) unless `--rom-xml` names the first.
- `--no-build-scripts` never writes them (the scripts pass it to the `v32as` they run; so does the environment variable `V32AS_BUILD_SCRIPT`).
- `--build-script-dir DIR` writes the scripts in DIR (which must exist) instead.

### Compatibility and diagnostics

- `--standard`: the official assembler, exactly; see [`--standard`](#--standard-the-official-assembler-exactly).
- `-w, --no-warnings` inhibits all warnings.
- `-s, --step` pauses per statement; `-v, --verbose` shows the encoded bit fields (to STDERR). Under `--standard`, `-s` does nothing and `-v` prints the
  official stage messages.
- `-h, --help`, `-V, --version`.

## Output files

### The .debug file

`OUTPUT.debug` is CSV, `address,file,line[,label]`, with one line per instruction; it is written next to the output
file (for `game.vbin`, `game.vbin.debug`). Plain `-g` is byte-identical to the official assembler's `-g program`;
the first label defined at an address is written as the fourth column.

**`;@src` markers (no `--map` needed).** A comment line of its own, `;@src FILE:LINE` (or `FILE:LINE:COL`; `;@src -` for "no source"), as
`v32lua -g` writes it (see V32DBG-SPEC). When the source has any marker, `OUTPUT.debug` gets `ADDRESS,FILE,LINE[,FUNCTION]` from them:
**one entry per marker, at the address of the first instruction after it** (so two consecutive markers naming the same line give two
entries; markers with no instruction between them give one, for the last). An instruction no marker starts has no entry (those before the first
marker have none at all). FILE is split from LINE at the last `:` (or the last two when both end in digits), so a drive letter is fine. The
marker must be the first thing on its line (a trailing `;@src ...` after an instruction is only a comment). Markers survive `%include` and macros
as the comments they are; the file name in the marker is what is written.

- **`;@src -`** (v32sim request): the first instruction after it gets the entry `ADDRESS,-,0` (file `-`, line 0, no function), so the sim knows
  where the last source line ends and the runtime begins. A malformed marker counts as `;@src -`. Instructions before the first marker still
  have no entry.
- **FUNCTION** is the function the instruction is in, written `NAME` (`__function_main:` -> `main`, `__function_f__l0:` -> `f__l0`); no fourth
  column outside functions. Every entry of a function has it, not only the first. Unlike plain `-g` (which writes the first label at the
  address) no other label is written in marker mode. A function starts at a `__function_NAME:` label and ends at the line
  `;@fn __function_NAME ...` that the Lua compiler writes after its body, at a `;@src -`, or at the end of the program. Functions nest (a Lua
  closure's body sits inside its parent's code, and the parent's code after it is the parent's again), and code between functions or after
  `;@src -` (global initialisation, the runtime) has no function. A `;@fn` written *above* a label (the runtime's `clobbers=` form) is not an
  end, for any language. `__function_NAME_return:` is not a function.
- **`;@lang X`** (a comment line of its own, before the first function; the first one counts, later ones are ignored): the language of the
  producer, `c` for `v32cc`, `lua` for `v32lua`. Two things depend on it. (1) With any language **other than `lua`** (compared without regard
  to case) functions do not nest, so **the next top-level `__function_NAME:` label ends the previous function**: its `;@var` ranges and
  blocks (closed or not) end at that label's address, exactly where the FUNCTION column changes, and no `;@src -` or `;@fn` is needed after
  the body. Without a `;@lang`, or with `lua`, nothing changes. (2) The language is recorded in the side files, see below.
- **`# lang X`**: when the source has `;@lang X` (and `--map` is not given), the **first line of `OUTPUT.debug`** is the comment
  `# lang X` (in marker mode only: with `-g` entries from `;@src` markers; a plain `-g` file and a `--map` file are unchanged) and the
  first line of `OUTPUT.vars` (when it is written) is the same comment. **Readers must skip every line that starts with `#`.** Without a
  `;@lang` there is no such line; under `--standard` markers are comments, so there is none either.
- **`--map FILE` still works**: for an instruction the map names, the map's entry is written; every other marker still gets its own. `v32cc`
  writes no markers today, so its output does not change.
- **`-C`**: the object stores the marker entries in place of the assembly lines (object format version 2; function word `0xFFFFFFFE` means "no
  function, and `v32asld -g` must not add a label"), so `v32asld -g` writes the same file as `v32as -g` on the joined source. The `--map`
  precedence is the same.
- **`--standard`**: markers are comments; `-g` writes the assembly lines as before.

### The .sym file

`OUTPUT.sym` (with `-g`, not with `--standard`; `OUTPUT` is the output file name, so `prog.vbin.sym`): the symbols with their **final** addresses, in the
format of v32cc's `NAME.asm.sym`, so that one file serves `nm`, a panic backtrace and a debugger. Addresses are always the ones the CPU sees
(`0x20000003`), whatever the `-g` mode. First the optional `# lang X` line (as in `.debug`), then:

```
# v32as symbols v1: kind,name,address,words,cfile,cline
F,main,0x20000003,10,t.c,3          a function: a top-level label followed by code; "__function_" is removed from the name
V,counter,0x00000010,1,,            a compiler variable: %define global_NAME number (words 0: not known) or var_NAME number (v32lua, words 1)
R,_helper_data,0x20000016,2,,       a top-level label followed by data
```

Order: functions, variables, data, each by address. `words` is the distance to the next top-level label (to the end of the program for the last
one); file-local labels (`function.local`) do not end a function. `cfile,cline` is the source position of the function's first instruction
(empty when there is none). The `V` addresses and sizes of `NAME.asm.sym` (which knows the C types) are the better ones when both exist;
this file adds the final addresses of functions and ROM data, which `NAME.asm.sym` gives as `@label` / `@rodata+OFF`.
`v32asld -g` writes the same file for the linked objects, without `V` lines (an object carries no `%define`s). Readers must skip lines that
start with `#`.

### The .vars file

`OUTPUT.vars` (with `-g`, next to `OUTPUT.debug`; only when the source has `;@var` lines; an old file is removed otherwise): the locals as
address ranges, which only the assembler can compute. Addresses as in `.debug` (`-g`, `-g vbin`, `-g v32`), END being the first address that
is out of scope. One CSV line each, in order of START (a block before its variables):

```
scope,START,END,DEPTH[,FUNCTION]
var,START,END,NAME,LOC,TYPE,FLAGS,DEPTH[,FUNCTION]
```

`LOC` is the `loc=` as written (`BP-3`, `BP+2`, `R5`, `@0x20003000`; `-` for `optimized-out`), except that a **symbol is resolved**: see
below. `TYPE` the `type=` (`-`
if none), `FLAGS` the bare words after it (`boxed`, `optimized-out`, joined by `+`; `-` if none; `key=value` words other than
`loc`/`type` are ignored). `DEPTH` is 0 for the function's own scope and 1, 2, ... for blocks in it, so the sim can pick the
innermost of two variables with the same name. The scope lines are the `;@scope {` ... `}` blocks.

- **Ranges.** A `;@var` is in scope from the first instruction after it. It ends at the `;@scope }` of the block it was declared
  in, or, with no block, at the end of the function; or at another `;@var` of the **same name in the same block** (a new home,
  e.g. the optimizer's `loc=R5`, or `;@var NAME optimized-out`). A same-name `;@var` in a *nested* block shadows and does not end
  the outer one. Empty ranges (`do end`) are left out. An unbalanced `;@scope }` is ignored and an open block is closed with its
  function (both warn under `-Wmarkers`).
- **`;@home FROM TO`** (an optimizer moved variables; `v32opt` writes it when it promotes a stack slot to a register): every variable in
  scope whose home (its current `loc=`) is `FROM` gets a new record from this point on, in the same block, with the home `TO`:
  `;@home BP-3 R5` where the value moves into R5, `;@home R5 BP-3` where it goes back. `TO` may be `optimized-out` (the value is gone;
  the record gets that flag and `loc` `-`). The old record ends here, so `NAME.vbin.vars` lists the variable once per home. A `;@home`
  that matches nothing is ignored. Like the other `;@` lines it is a comment for every other tool.
- **Symbol locations.** A `loc=SYMBOL` where SYMBOL is a label, `label+N` / `label-N` (N decimal or `0x...`), or a name `%define`d as a
  number or as one of those (v32lua's `%define var_NAME 0x78`; the replacement text must be just that, no other expression) is written in
  the LOC column as `@0xADDRESS` when it is known at the end of the assembly. A label gives its address in the style of the START and END
  columns of the `-g` mode (absolute for `-g`, the file offset for `-g vbin` / `-g v32`); a `%define`d number is a plain value (a RAM
  address) and is written as it is, whatever the mode. Registers (`BP-3`, `BP+2`, `R5`, ...), `@0x...` and `-` are left as written, as is a
  symbol that is not known (it also warns under `-Wmarkers`). The `%define`s in force at the end of the file count.
- **Multi-file (`-C`).** The object stores the records (object format version 3, or 4 with a `;@lang`, see `docs/OBJECT.md`) and `v32asld -g`
  writes `OUTPUT.vars` and `OUTPUT.debug` as `v32as -g` would for the joined source; `v32asld -R` keeps them. A `%define`d number is
  resolved when assembling; a label (of the object, or a global one of another object) is resolved by `v32asld` with its final address, in the
  `-g` mode given to the linker. Several objects: the first `;@lang` found is the one written. Tested with two files, one function each,
  and with C-style files.
- `--standard`: the `;@` lines are comments; no `.vars`.

Example (`m.asm` has the lines `;@src prog.lua:1`, `__function_main:`, `;@scope {`, `;@var x loc=BP-1 type=int`, two `mov` instructions, `;@scope }`,
`;@fn __function_main` and a `hlt`; `v32as -g m.asm` writes `m.vbin.vars` containing):

```
scope,0x20000000,0x20000004,1,main
var,0x20000000,0x20000004,x,BP-1,int,-,1,main
```

### The -r (relocation) file

**Format of the `-r` file** (a loader may depend on it): one line per word, sorted by `index` (ascending, no duplicates); `index` is the **zero-based word index into the image**, not a byte offset and not counting the 3-word VBIN header (the first instruction is word 0); `0xVALUE` is the value **as assembled**, i.e. at the base the image was assembled or linked for, so a loader that places the image at `new_base` adds `new_base - assembled_base` to a `C` word (and, for a `D` word, the displacement of the data) and leaves other words alone; the optional third column is `C` or `D` and is present on every line if the source (or any linked object) declares a `datasym`, on none otherwise. Both `v32as -r` and `v32asld -r` write exactly this.

A source that declares `datasym NAME` (enhanced syntax; the value of `NAME` is 0, so `NAME+17` is a word holding 17) gets a third column, `,C` for a code address (moves with the load address) and `,D` for a reference to a datasym (moves with the base of the module's data). `v32cc --pic-data` writes every global's address that way. A datasym can be used with `-C` too; `v32asld -r` then writes the same column.

### The --symbols file

One line per label, `0xADDRESS,name,kind`, sorted by address. Kind `F`: code follows; `D`: data follows (or nothing). With `--symbols-all`:
file-local labels as `function.local`, kind `V` for each `%define global_NAME number` (the number in the address column), and `N,DATASYM+N,V` for
each `DATASYM+N` the program refers to. `v32asld --symbols` writes the same for a linked program (local labels under the name the assembler gave
them, e.g. `_f__loop`).

## Objects and the linker

`v32as -C x.asm` writes a relocatable object `x.v32ob`; `v32asld a.v32ob b.v32ob -o prog.vbin [-b|-c|-O ADDR] [-g] [-r FILE]`
links them. `global _name` / `extern _name` (plain names, no `%`) say which labels are shared. Linking
equals assembling the sources as one file; the objects carry the debug records, so `v32asld -g` writes the
same `.debug` file. Format and details: `docs/OBJECT.md`.

`datasym` is accepted by `-C`; the object records it (object format version 2) and `v32asld -r FILE` (also `--emit-relocs FILE`) writes the third
column, `,C` or `,D`, as `v32as -r` does. A datasym has the value 0 in every object and is not moved by the link.

### v32asld options

- `-o, --output FILE` (default `a.vbin`; `a.v32ob` with `-R`); `-b, --bios`, `-c, --cart` (default), `-O, --origin ADDR`.
- `-g, --debug[=MODE]` writes `OUTPUT.debug` (and `OUTPUT.vars` when the objects have `;@var` records; both start with `# lang X` when
  the objects were made from a source with `;@lang X`, and the symbol locations of `;@var` are resolved; also `OUTPUT.sym`, see
  [The .sym file](#the-sym-file)); `-r, --relocs FILE` (also `--emit-relocs FILE`)
  the relocation list (format above); `--symbols FILE` the label table.
- `-A, --archive FILE` makes an archive (`V32-VARC`) of the objects given, instead of linking. Archives given as operands or with
  `-L DIR -l NAME` (`DIR/NAME.v32a`, else `DIR/libNAME.a`; `.` is always searched last) are mined after the objects, a member being linked
  only when it defines a symbol still undefined.
- `--entry SYMBOL` puts a two-word `jmp SYMBOL` first unless the symbol is already the first word.
- `--v32x --data N [--entry SYMBOL|OFFSET]` writes a V32X executable (header + image linked at 0x100000; `-O` changes the base; `-b`/`-c` and `-g vbin|v32`
  are refused).
- `-R, --relocatable` is a partial link: `v32asld -R -o ab.v32ob a.v32ob b.v32ob` (not `-r`, which is the relocation list) joins
  objects into one object. Globals stay global, an `extern` another input defines becomes a reference to it, the
  others stay `extern`; relocations, datasyms and debug records are kept, so linking `ab.v32ob` equals linking
  `a.v32ob b.v32ob`. Archives and `-l` work as in a full link. It refuses `-b -c -O -g -r --symbols --entry --v32x`.
- `-w, --no-warnings` does not warn about an `extern` that no code uses.
- Errors: ``undefined reference to `x' (first used in a.v32ob)``, once per symbol; a global defined by two objects; a bad or truncated object.

## The language

### Data directives

`integer`, `float`, `pointer`, `string`, `zstring`, `datafile`. One word per element; `string` is one word per character plus a terminating 0.
`zstring` is byte-packed: four characters per word (first character in the low byte), zero-terminated, last word zero-padded. (`zstring` is not
in the official assembler; its golden file is hand-verified, not official output.) `datafile` reads little-endian words.

**`datafile` search**: absolute path; the directory of the file holding the directive; each `-I DIR`; the current directory. The error lists the
places tried: `cannot open data file "x" (looked in out/, ../data/, .)`. `--standard` keeps the two old places (the file's directory and the
current directory; no `-I`, as for `%include`).

`global`, `extern` and `datasym` are described under [Objects and the linker](#objects-and-the-linker) and `-r`.

### Numbers, names, labels

Hexadecimal `0xFF` and `FFh`, binary `0b1010`, octal (a leading zero), decimal `42` and `#42`, floats `3.14`, character literals `'A'`, `true`/`false`.
Labels and a statement may share a line; mnemonics and registers are case-insensitive. A label starts with an underscore.

### Label plus constant

Wherever a label is accepted as a value, `label + integer` or `label - integer` is too (one label, one
constant): `mov R0, _tab+2`, `mov R1, [_tab+3]`, `mov [_tab-1], R1`, `jmp _f+4`, `pointer _tab+1, _end`. It is
resolved like a plain label (forward references included). `--standard` refuses it.

### `--standard`: the official assembler, exactly

`--standard` turns every extension off, for a drop-in replacement of `assemble` (and for checking that a
program is portable to it):

| area | in `--standard` |
|---|---|
| numbers | `0b101`, `FFh`/`2Ah`, `#42` and `0X1F` are errors. A leading zero is **decimal** (`0100` is 100), as the official tool reads it |
| names | `IP`/`IR`/`IV` (internal registers) and `zstring` do not exist |
| directives | only the stock ones, spelled in lowercase; no `%if %elif %assign %eval %includeonce`, no function-like macros (`%define F(x) ...` defines the plain macro `F` whose value starts with `(x)`), no `.local` labels, no `__FILE__`-style symbols |
| `%define` | a value that contains its own name, or a `%`, is an error |
| `%include` | `"file"` only, relative to the including file only (no `-I`, no `<file>`) |
| operands | `label +/- integer` is an error |
| `datafile` | looked up next to the source file, then in the current directory (no `-I`) |
| command line | one input file only; `-s` does nothing; `-v` prints the official stage messages |
| unterminated `%if` | a warning (the official tool accepts it silently) |

Without `--standard`, the same program is accepted too, with one trap to know about: a number with a
leading zero is **octal** here (`0777` is 511) but **decimal** in the official assembler. `v32as` warns
about every such literal; use `--standard`, or drop the leading zero.

## Preprocessor

Source is preprocessed before it is assembled (`-E` shows the result). Design notes are in
`docs/PREPROCESSOR.md`. A directive is a line whose first non-blank character is `%`; directive names are
case-insensitive, macro names are not. Macros are replaced only in code: never inside strings,
character literals, comments or numbers.

### Everything the official assembler has

```
%define NAME tokens...      %undef NAME
%ifdef NAME   %ifndef NAME  %else   %endif
%include "file"             %error "message"   %warning "message"
```

`%define NAME value` is expanded where it is *used* (late binding), and a macro is never re-expanded
inside its own expansion. `%include` paths are relative to the including file's directory (limit: 20
levels). Skipped `%ifdef` blocks drop every line, including unknown directives. An unterminated block is
an error (the official tool lets it pass; `--standard` does too, with a warning).

### Extensions

- **Function-like macros**: `%define MUL(a, b) ((a) * (b))`, used as `MUL(3, 4)`. Arguments are expanded
  before substitution. `#x` makes a string of the argument, `a ## b` joins two tokens
  (`%define LAB(n) _label_ ## n`), `...` / `__VA_ARGS__` take the remaining arguments (and `, ## __VA_ARGS__`
  drops the comma when there are none). `#` followed by a digit stays the `#42` number syntax. A name
  followed by `(` is only an invocation when the macro is function-like.
- **`%if expr`, `%elif expr`, `%elifdef`, `%elifndef`**, `%else`, `%endif`.
- **Expressions** (`%if`, `%assign`, `%eval`): integers (32-bit, wrapping) and floats (32-bit), all the
  number forms the assembler reads, `defined(NAME)`, `true`/`false`, the port and constant names the
  assembler knows, operators `( ) + - ! ~ * / % << >> < <= > >= == != & ^ | && || ?:` with C precedence
  (`&&`, `||` and `?:` do not evaluate what they skip), and the functions `int() float() abs() min() max()
  floor() ceil() round()`. An operation with a float operand is a float operation (`7/2` is 3, `7/2.0` is 3.5).
- **`%assign NAME expr`** computes a value now: `%assign N N + 1`. (`%eval NAME expr` is the same.)
- **`%eval(expr)`** anywhere in a line is replaced by the value: `mov R0, %eval(WIDTH * 2 + 1)` becomes
  `mov R0, 641`. This is what lets symbols take part in arithmetic, which `%define MATH A+B` cannot do:
  the assembler has no expressions, so the sum has to exist as a number in the source. Floats are written
  back in the shortest form that reads back as the same float.
- **`.local` labels**: after a global label `_draw:`, the name `.loop` means `_draw__loop`
  (so `.loop:` defines it and `jt R1, .loop` uses it).
- **Symbols**: `__FILE__`, `__LINE__`, `__COUNTER__`, `__INCLUDE_LEVEL__`, `__V32AS__` (version date as a
  number), `__BASE__` (first address), and one of `__BIOS__`, `__CART__`, `__ORIGIN__`, `__NONE__`.
  A `%define` of the same name wins.
- **Includes**: `%include <name>` searches only the `-I DIR` directories; `%include "name"` tries the
  including file's directory first and then the `-I` directories. `%includeonce` in a file makes any later
  `%include` of it a no-op.
- **Command line**: `-D NAME[=VALUE]` (value defaults to 1), `-U NAME`, `-I DIR`, `-E` (print the
  preprocessed source with `# LINE "FILE"` markers, `-P` without them).
- **`%title`, `%version`, `%texture`, `%sound`**: the ROM definition, for `--rom-xml` and `--build-scripts`; see
  [Cartridge definition and build scripts](#cartridge-definition-and-build-scripts).
- **`%idefine`, `%xdefine`, `%ixdefine`**: a case-insensitive define; a define whose value is expanded
  now rather than where it is used; both.

### Macros that write instructions

```
%macro CLAMP reg, lo=0, hi=255        ; named parameters, with defaults
    imax  reg, lo
    imin  reg, hi
%endmacro

%macro COUNTDOWN reg, count
    mov   reg, count
%%top:                                ; private to each expansion (becomes __M<serial>_top)
    isub  reg, 1
    jt    reg, %%top
%endmacro

    CLAMP R3, , 100                   ; invoked like an instruction (labels may come first)
    COUNTDOWN R1, 10
```

- **`%macro NAME params` ... `%endmacro`**. Parameters are `name`, `name=default` (a default makes it
  optional; an empty argument takes the default) and a last `rest...` (or `...`) that takes the remaining
  arguments. `%macro NAME 2`, `1-3` or `1-*` only fixes how many arguments there are. Inside the body a
  parameter name, or `%1` `%2` ..., stands for its argument text, `%0` for the number of arguments and `%*`
  for all of them. Arguments are split at commas outside `()` `[]` `{}` and quotes; `{a, b}` passes a comma
  as part of one argument. A macro may be defined several times if the argument counts differ; `%unmacro NAME`
  removes it.
- A macro name is **case-sensitive** (`%imacro` makes it case-insensitive) and **wins over an instruction** of
  the same name, with a warning unless `%pragma shadow` (everything) or `%pragma shadow NAME, ...` allows it.
- **`%rep count` ... `%endrep`** repeats its body (at most 1,000,000 times); `%@` is the iteration number.
  `%exitrep` leaves the loop. Loops nest and may contain macros and conditionals.
- **`%exitmacro`** leaves the macro (also from inside `%if` or `%rep`). **`%rotate n`** rotates what `%1`
  `%2` ... refer to (left for positive `n`), the way to walk a variadic list:
  `%rep %0` / `push %1` / `%rotate 1` / `%endrep`.
- **`%%name`** is a label private to one expansion of a macro (one per iteration for a `%rep` outside a macro;
  inside a macro it is the macro's, so use `%%name_%@` for one label per iteration).
- **Operand tests**, usable as `%ifXXX` and `%elifXXX`, and negated with `n` (`%ifnreg`):
  `reg` (a CPU register), `sysreg` (`IP` `IR` `IV`), `num` (a constant expression; a bare port name is not
  a number), `str` (a string literal), `label` (`_name` or `.name`), `port` (an I/O port name),
  `idn a, b` / `idni a, b` (the same text, exactly or ignoring case), `empty`, `macro NAME [count]`, `ctx NAME`.
  The text is macro-expanded first. This is what lets one macro choose between `mov` and `in` according to
  its operands, and report a bad operand with a real message (`%error "INC wants a register, got %1"`).
- **Strings**: `%strlen N "text"`, `%substr S "text", start [, length]` (start counts from 1), `%strcat S "a",
  "b"`, `%defstr S tokens` (the expanded tokens as a string).
- **Contexts**: `%push name` ... `%pop` (`%repl name` renames). `%$x` is a name private to the innermost
  context (`%$$x`: the one below), which is what lets macros like `IF` / `ELSE` / `ENDIF` share labels.
  `%ifctx name` tests the innermost context.
- **`%pragma once`** (same as `%includeonce`), `%pragma shadow ...`.

`lib/v32as.inc` has ready-made `INC DEC ZERO NEG CLAMP SWAP PUSHALL POPALL WAIT_FRAMES` (all check that their
operands are registers) and `lib/control.inc` has `IF` / `ELSE` / `ENDIF` and `WHILE` / `ENDWHILE`; use them with
`-I lib` and `%include "v32as.inc"` (manual pages `v32as-inc(3)` and `v32as-control(3)`).

### Limits

A macro expansion is limited to 64 levels, and a run to about 4 million replayed lines (runaway `%rep` or
recursion stops with an error). `%include` nesting is limited to 20 levels and a `%rep` to 1,000,000 iterations.
Errors from inside an expansion are reported at the line of the invocation with a
`note: in expansion of macro 'X' (defined at file:line)`; `-g` also attributes the generated code to
the invocation.

## Cartridge definition and build scripts

A cartridge is a program plus the textures and sounds it uses, packed by `packrom` from an XML definition. A program written in C
(`v32cc`) says what goes into the ROM with `#texture`, `#sound`, `#title` and `#version`; `v32as` has the same four as preprocessor
directives, and can write the definition and the scripts that build the cartridge. All of it is an extension (not under `--standard`),
and it changes nothing in the assembled program.

```
%title   "Space Rocks"            ; the name in the cartridge (at most 63 characters; the last %title wins)
%version 1.2                      ; MAJOR.MINOR, digits.digits (packrom accepts nothing else: an error otherwise)
%texture TEX_FONT  "gfx/font.png" ; TEX_FONT becomes the number of this texture: 0, 1, ... in order of appearance
%texture TEX_SHIP  "gfx/ship.png"
%texture           "gfx/old.vtex" ; the name is optional
%sound   SND_BOOM  "snd/boom.wav" ; sounds are numbered on their own, from 0

    mov R0, TEX_SHIP              ; the number select_texture takes
    out GPU_SelectedTexture, R0
```

- `NAME` is an object-like macro holding the number, so it works wherever a number does (`mov R0, TEX_SHIP`, `%if`, `%eval`). Textures and
  sounds are numbered separately, in the order their files first appear; naming the same file again gives the same number. This is the numbering
  `packrom` gives the entries of the definition, so the program and the cartridge agree.
- The file is looked for next to the source file holding the directive, then in the `-I` directories (what `datafile` does); the
  name as written goes into the definition. A file that is not found is a warning (the script then uses the name as written).
- Directives in a skipped `%if` block, or in a macro that is never expanded, count for nothing; inside an `%include`d file they work, so a
  shared `resources.inc` is a good place for them.
- With `-C` (objects) the directives are accepted but not stored: a warning says so. Give them in the source of the final `v32as` run.

**`--rom-xml FILE`** writes the definition after a successful assembly:

```
<?xml version="1.0" encoding="UTF-8" standalone="no" ?>
<rom-definition version="1.0">
    <rom type="cartridge" title="Space Rocks" version="1.2" />
    <binary path="game.vbin" />
    <textures>
        <texture path="font.vtex" />
        <texture path="ship.vtex" />
        <texture path="gfx/old.vtex" />
    </textures>
    <sounds>
        <sound path="boom.vsnd" />
    </sounds>
</rom-definition>
```

The type is `bios` with `-b`. Paths are relative to the XML file. A `.png` texture or `.wav` sound is named as the `.vtex` / `.vsnd` file
that `png2vircon` / `wav2vircon` make from it, placed next to the XML (two with the same base name get `_2`, `_3`, ...); any other file is
named as it is, by its path from the XML. Without `%title` the title is the output's name, without `%version` it is `1.0`. Text is
escaped (`&amp;` and so on).

**`--build-scripts`** writes `Make.sh` and `Make.bat`, which rebuild the cartridge from the sources, from the optimizer on:

1. **Optimize**: `v32as -E -P` writes the preprocessed source (`FILEPre.asm`), then `v32opt -O3 FILEPre.asm -o FILEOpt.asm`; only when `v32opt` is on the
   `PATH` (or `V32OPT` names it) and `NO_OPT` is not set. `V32OPT_FLAGS` replaces `-O3`. The optimizer gets the preprocessed text because it does not
   know `%macro`, `%if` or `%rep`: it reads every branch as code that runs in turn, and it deleted a `mov` that the `%else` branch "overwrote".
2. **Assemble**: `v32as` again, with the options of the run that wrote the script (`-b`/`-c`, `-D`, `-U`, `-I`, `-w`, `-W...`, `-g`, `--map`)
   plus `--rom-xml` / `--rom-xml-opt`, so the definitions follow the `%title` and `%texture` lines on every build; then the same for `FILEOpt.asm`.
3. **Convert**: `png2vircon IN.png -o OUT.vtex` and `wav2vircon IN.wav -o OUT.vsnd` for each resource that needs it.
4. **Pack**: `packrom NAME.xml -o bin/NAME.v32`, and `packrom NAMEOpt.xml -o bin/NAMEOpt.v32`.

The optimized cartridge is a bonus: if `v32opt` fails, or its output does not assemble, the script says so and still builds `bin/NAME.v32`.
With more than one source file there is no optimized build. `v32opt` is built for compiler output (`__function_NAME:` labels): on hand-written
code it mostly does peephole work, and it calls `-O3` aggressive, so compare the two cartridges before trusting the `Opt` one. `V32AS`, `V32OPT`, `V32OPT_FLAGS`, `PACKROM`, `PNG2VIRCON` and `WAV2VIRCON` name tools that are not on the `PATH`. Paths in the
scripts are relative to the script's directory, and `Make.sh` changes to it itself, so it can be run from anywhere. A script ends with
`BUILD SUCCESSFUL` (exit 0) or `BUILD FAILED` (exit 1).

A script in the middle of a build is never rewritten, and a script you wrote is never replaced:

- A script carries the line `Generated by v32as` as a comment of its own (`# ` or `REM `). A `Make.sh` or `Make.bat` without it, including one
  written by `v32cc`, is left alone with a warning (`--no-build-scripts` silences it). Delete the line from a generated script to keep your edits.
- The scripts call `v32as` with `--no-build-scripts` and set `V32AS_BUILD_SCRIPT=1`, which `v32as` treats the same way, so a `v32as` started from
  inside a build (by a wrapper, or a Makefile calling the script) cannot rewrite the script that is running.
- A script whose text would not change is not touched at all. One that has to change is written to a temporary file and renamed over the old
  one, so a shell that is executing the old `Make.sh` keeps reading the old text. (`cmd.exe` reads a `.bat` by position, so for `Make.bat`
  the first two points are what protect it.)

The tests are in `tests/rom_tests.sh` (`make test`), with stand-ins for `packrom`, `png2vircon`, `wav2vircon` and `v32opt`; `Make.bat` was
checked by reading, not by running it on Windows.

## Internal registers (extension)

`IP`,  `IR`, `IV`  are not  CPU-addressable, but  `MOV` accepts  them and
expands to exactly one real instruction, using no hidden scratch register
(A = address of the expansion):

| source               | expands to              | meaning                                   |
|----------------------|-------------------------|-------------------------------------------|
| `MOV Rn, IP`         | `MOV Rn, A+2`           | address of the next instruction           |
| `MOV Rn, IR`         | `MOV Rn, <this word>`   | encoding of the instruction being executed|
| `MOV IP, Rn / addr`  | `JMP Rn / addr`         | jump                                      |
| `MOV IR, Rn`         | `MOV [A+2], Rn`         | overwrite the next instruction word       |
| `MOV IV, Rn`         | `MOV [A+3], Rn`         | overwrite the next instruction's immediate|

`MOV Rn, IV` is rejected (self-referential); IR/IV cannot be written from
an immediate. The IR/IV writes patch code  at run time, so that code must
run from RAM (the assembler warns in --bios/--cart mode). `MOV Rn, IP` in
--none mode is relative to address 0 (warns).

## Verification

Output is  byte-identical to the  official Vircon32 assembler  for: every
opcode in every  legal operand form, all I/O ports  and port values (BIOS
and CART), and all data directives. `tests/golden/*.hex` were produced by
the official assembler. `make test` runs the golden, differential and error-message tests.

## History and compatibility

`v32as` began as a C port of the bash `v32as` (same job: assemble Vircon32 assembly to a VBIN, with a listing/verbose/step mode and an
interactive REPL), with flex for the lexer, bison for the parser and hash tables in place of bash arrays and `bc`. Differences from the bash version:

- The VBIN header carries the real word count (bash hard-coded 155).
- Numeric ports in `IN`/`OUT` work (bash bug); unknown/truncated ports warn.
- Integer literals given to float-class ops are converted to float; ATAN2/POW take registers only (as official).
- `[R+0]` is encoded as `[R]` (as official).
- The data directives are `integer`, `float`, `pointer`, `string`, `zstring`, `datafile` (see [Data directives](#data-directives)).
- Added: `true/false`, character literals, `0b`, octal, `#dec`, `h` suffix numbers; labels and a statement may share a line;
  mnemonics/registers are case-insensitive.

What changed in which development round is in `CHANGES.md`.
